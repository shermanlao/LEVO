# Public product catalog API

Public `GET` catalog routes are available on the site origin (`/api/products`, …) via a GET-only Next proxy. `POST` / `PUT` / `PATCH` / `DELETE` on those public paths return **405**. Create / update / delete go through `/api/admin/backend/...` with an admin session. Direct access to Express is loopback-only (`127.0.0.1:3333`).

Express (`backend-server`) serializes **detail** products in [`serializeProduct.ts`](../backend-server/src/lib/serializeProduct.ts) (`by-slug`, `by-path`, `:id`). List endpoints (`GET /api/products`, `/featured`, and nested series `products.data`) use `serializeProductListItem` — card fields (name, slug, wattage, cct, beam, dimming, dimensions, cutout, colour, trim colour, one image, series/type/path). Product types and series are serialized the same way in their controllers (`{ id, attributes }`, nested `product_type`, `featured_image: { data }`). Series `featured_image` is the 16:9 catalog crop (same Strapi media object as types; `{ data: null }` when empty). Series also serialize `featured_image_source`, `featured_image_page` (4:5 gallery), and `featured_image_datasheet` (1:1 PDF / thumbs). Empty chunks fall back to source, then `featured_image`. Single-series lookups (`by-slug` and `:id`) also include `attributes.products.data` (size packs), `attributes.options` (with catalog `code` and `label_image` copied on), `attributes.appearance_photos`, `attributes.datasheet_labels`, nested `product_type.attributes.datasheet_labels`, and `attributes.description_phrase` so `/products/[type]/[series]` can render selectors, the cartesian option table, datasheet icons, and the filled SKU-dialog / datasheet phrase. Series list rows include `options`, `option_count`, `product_code`, and `is_featured` (no nested products). `/products/[type]` renders one **series card** per series; an active filter keeps series cards that have matching variant tags. `/products/[type]/[series]` shows the gallery, variant selectors, and generated combinations. `/products/[type]/[series]/[slug]` redirects to the series. Homepage featured uses `GET /api/product-series/featured`. Search uses `GET /api/product-series?q=`. Raw Sequelize rows must not be returned for types, series, or products.

The Next.js client still unwraps both shapes with [`strapi-entity.ts`](../frontend/src/lib/strapi-entity.ts) (`asStrapiEntity` / `asStrapiList` / `normalizeStrapiEnvelope`) at fetch boundaries. Never read `row.attributes.featured_image` without that unwrap or optional chaining — that is the crash that hit admin Product Types and Product Series.

Public series lookup uses `GET /api/product-series/by-slug/:slug` (not `/api/product-series/:slug`, which is treated as a numeric id).

| Method | Path | Notes |
|--------|------|--------|
| `GET` | `/api/product-types` | All types (Strapi-like) |
| `GET` | `/api/product-series` | All series with nested `product_type` (no product list). Optional `q`, `featured=1` |
| `GET` | `/api/product-series/featured` | Featured series for the homepage |
| `GET` | `/api/product-series/by-slug/:slug` | By series slug, including `attributes.products.data` (size packs) |
| `GET` | `/api/product-series/:id` | Numeric series id, including `attributes.products.data` (list payload) |
| `POST` | `/api/admin/backend/product-series` | Admin session. Create (name + slug required). Express still accepts this on loopback `/api/product-series` |
| `PUT` | `/api/admin/backend/product-series/:id` | Admin session. Update (optional `options` array replaces `series_options`; optional `ldt_family`) |
| `DELETE` | `/api/admin/backend/product-series/:id` | Admin session. Delete; products in that series keep their rows but `series_id` is cleared |

Product endpoints:

| Method | Path | Notes |
|--------|------|--------|
| `GET` | `/api/products` | List payload (`serializeProductListItem`). Optional `q`, `series` (or `filters[series][slug]`), and `filters[product_type][slug]`. Cached `public, s-maxage=120, stale-while-revalidate=600` |
| `GET` | `/api/products/featured` | Legacy; homepage now uses featured series |
| `GET` | `/api/products/by-slug/:slug` | By product slug |
| `GET` | `/api/products/by-path/:type/:series/:slug` | Looks up by **slug** (type/series in the URL are for the public path; mismatch still returns the product so the page can redirect) |
| `GET` | `/api/products/:id` | Numeric id, or slug if the param is not a number |

Datasheets are generated by Express `GET /api/datasheets/:slug` (rewritten from Next.js; see [product-datasheet.md](product-datasheet.md)). They are not static files.

LDT files **are** stored on disk when a product is created or updated (`products.ldt_file`, `frontend/public/uploads/product-ldt/…`). `GET /api/products/:id/ldt` sends that file (see [photometric-ldt.md](photometric-ldt.md)).

Custom series files (variant query params must match `series_options`): `GET /api/series/:slug/datasheet`, `/installation`, `/ldt`. See [series-configurator.md](series-configurator.md).

`by-slug` and `by-path` are registered **before** `/:id` so `by-slug` is not treated as an id.

Missing products return **404**. Public SKU pages no longer render; they redirect to the series.

`product_code` is the LEVO SKU (`DL00007`). Partner article and model are `vendor_code` / `vendor_model` (shown in admin, not in catalog specs). Public `name` is spec-based (e.g. `10W LED Downlight`). See [product-codes.md](product-codes.md).

Remote partner photos are rewritten to `/api/product-media/:id/:field` so the catalog never exposes the LightX hostname. Express caches those bytes (memory + `backend-server/cache/product-media`) and coalesces in-flight downloads. See [partner-catalog-import.md](partner-catalog-import.md).

Image fields are mixed types: `main_image_A` (and similar) are **strings**; `featured_image` is a Strapi media object `{ data: { attributes: { url } } }`. The catalog unwraps both with `extractImageSrc` / `toPublicImagePath` in `frontend/src/lib/image-utils.ts`. Do not call `.startsWith` on a raw image field.

Admin product edit (`/admin/products/[id]`) uses the same unwrap in `ProductImageUploader` and `ProductImage` (`resolveProductDisplaySrc` in `image-utils.ts`) so a Strapi media object for `featured_image` does not throw `imagePath.startsWith is not a function`. Never append `.jpg` onto `/api/product-media/:id/:field` — the field name is not a filename.

`PUT` / `POST` `/api/products` store image columns as **strings**. `unwrapProductBody` in `productController.ts` coerces a Strapi media object (or legacy `featured_image_id`) to a URL and **omits** `/api/product-media/:id/:field` values so a save does not overwrite the stored remote partner URL. Admin Save uses `toPersistedImageValue` in `image-utils.ts` for the same unwrap.
